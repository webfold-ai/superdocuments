# Remaining differences from Pandoc 3.1.3

Every document with a difference in `results/sd-after.json` is in the table at the end (generated by
`python3 disagreements.py`, which exits non-zero if a difference has no cause). The cause of each is one of the
codes below; each was checked by reading the diff of at least one document it covers, not guessed from the counts. A code is
a claim about *why*; the verdict says who is wrong.

| Code | Verdict | What differs |
|---|---|---|
| L1 | ambiguous, ours kept | LaTeX `algorithmic` pseudocode: we keep the source as a `latex` code block (nothing is lost); Pandoc drops the `\State`, `\For` commands and keeps only the `$...$` inside. We also write the caption ("Algorithm 1: ..."), Pandoc has none. 28 documents. |
| L2 | ours extra, intentional | A `.bib` named by `\bibliography` or `\addbibresource` makes `convert_path` append the references the document cites (key, formatted entry); Pandoc without `--citeproc` appends nothing. 11 documents, including both low hand-written ones. |
| L3 | ambiguous | siunitx quantities: `\num{1.6e-19}` is read by us as "1.6 x 10^-19" with Unicode superscripts, by Pandoc as `10^-19^` (superscript markup). 1 document. |
| L4 | ours wrong, not fixed | LaTeX: an emphasis, a footnote or a bold label that Pandoc has and we lack (or the reverse) that none of the rules above explains: `paper-sparse-attention` (footnote in a float caption), `paper-notes-algorithms` (emphasis). |
| X1 | representation limit | A cell that spans columns or rows: a Markdown pipe table repeats it in each covered column, Pandoc counts it once, so our count is higher by the extra cells (DOCX, EPUB, HTML, LaTeX `\multicolumn`). 28 documents. |
| D1 | Pandoc quirk | DOCX list items whose paragraphs carry `w:ind` with a hanging indent (LibreOffice writes them) come out of Pandoc as a block quote inside each item. We read them as list items. Indented paragraphs outside lists do become quotes in both. 14 documents. |
| D2 | ours wrong, not fixed | One superscript Pandoc does not see (`docx-lo-30`). |
| O1 | ours extra, intentional | ODT written by LibreOffice: the styles `Source Text`, `Preformatted Text` and `Horizontal Line` are read as inline code, code block and rule; Pandoc's ODT reader has no mapping for them and gives plain text. 27 documents. |
| O2 | ours wrong, not fixed | ODT: indented paragraphs Pandoc reads as block quotes that we keep as paragraphs, and a few emphasis, row and link-target details. 17 documents. |
| E1 | ours wrong, not fixed | EPUB written by Pandoc: one italic run less in the equations Pandoc wrote as `<em>`/`<sup>` markup (`epub-pandoc-01`, `-02`, `-04`). |
| H1 | ours extra, intentional | HTML: `<span class="math inline">\(..\)</span>` is math for us and a plain span for Pandoc 3.1.3; `<kbd>` is code for us and a span for Pandoc. 2 documents. |

## Limits of the comparison

- Where Pandoc's behaviour was matched on evidence from the corpus (the BibTeX-to-CSL conversion: sentence-casing
  of Title Case titles, `howpublished`/`school` to `publisher`, `location` only for BibLaTeX files, dropping particles; the locator labels
  Pandoc recognises, which are the locale's own terms; `page` ranges getting the style's `page-range-delimiter`),
  the rule was inferred from outputs and may be wrong outside the corpus.
- The hand-written LaTeX has six documents; its 0.779 mean is dominated by L2 and says little about LaTeX in general.
